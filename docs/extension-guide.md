# 原浏览器扩展使用说明（保留的 0.7 功能）

以下为升级前指南。1.0 后台增加面试 Agent；本文“无云端模型”仅指原扩展的本地推荐，不包含可选面试模型服务。新增 Agent 以根 README 为准。启用远端口令时请使用 Agent 页面；旧扩展仍面向无口令 localhost 后台。

# 求职表单助手

Chrome / Edge 扩展 + 本地素材库。保存多份简历和项目表述，根据岗位关键词选择材料，再辅助填写招聘申请表。扩展与后台版本 0.7.0，使用本地关键词与上下文规则，不需要大模型 API Key。

## 0.7.0：意向城市与教育经历下拉选择

- 后台“意向城市”按优先顺序填写，例如 `北京、南京、上海、郑州`。第一、第二意向栏各匹配一个城市；优先城市不可选时尝试后续已存城市，避免与页面已有选择重复。支持 `北京市` 与 `北京`，不会把整个城市列表输入单选搜索框，也不随机选择未保存的城市。
- 学校、专业、学历支持原生、可搜索下拉及有关联列表标记的控件。展开、搜索、点击唯一匹配选项后再核对结果；仅输入搜索词不算成功。学历支持“本科／大学本科”“硕士／硕士研究生”等明确等价写法，学位栏区分“学士／硕士”。不把相似校名、专业大类当成同一个选项。
- 插件读取全部教育记录。页面本科／硕士标题或已填学校明确时分别匹配；结构清楚的空白多段卡片按已存入学时间从新到旧分配。只有一段时使用默认教育记录。无法确定对应关系会提示，不复制同一学校到所有教育栏。请先在后台分别保存本科和硕士。
- 入学、毕业时间支持普通文本和原生日期／月份控件；只保存年月时不编造某一天。已有手填内容保留。旧插件标记为已填、实际却还是整串意向城市的搜索文字，可清理后重新选择。
- 普通填写按钮也显示具体跳过原因。没有匹配选项、前置国家／地区未填、网站控件重新加载时会提示，不以绿色边框假装完成。

更新：在扩展管理页重新加载 **0.7.0**，再刷新招聘页面。个人资料不需要重新录入；若旧页面仍留有一整串城市，请清空该搜索框后重试。本地演示页另提供“城市与教育下拉试填”，验证选中状态。此版本通过合成表单测试，具体招聘网站、级联地区／专业目录、自定义日期弹窗仍可能需要专门适配；不自动提交申请。

## 0.6.0：跨网站表达与上下文识别

- 结合中英文同义词、字段标签、aria-labelledby、占位提示、camelCase/snake_case 属性与单字段容器文字识别资料。区分个人姓名、学校名、项目名和父母姓名，避免混填。
- 不再要求页面出现“基本信息”“岗位职责”等固定标题。结合多个申请字段或申请路径判断表单；学校单独一页的填写步骤也可识别。登录、订阅、院校搜索与公司目录不按岗位表单处理。
- 岗位要求可从“工作任务／我们希望你／What you will do”等表达判断；优先利用标准 JobPosting 结构化数据。列表页有多个岗位时不会直接选择第一条。
- 申请页只有唯一、明确、同站点的“职位详情／View job details”链接时，尝试读取该页面要求。只请求已存在的详情链接；动态加载或无法确认的页面沿用已识别岗位或提示先打开详情。
- 简历与项目匹配加入常见技术中英别名，如 CV／计算机视觉、模型评估／model evaluation。C/C++、TCP/IP 标签保持完整，重复关键词不会堆高分数。
- “字段已识别但后台未填”“页面已有值”“日期精度不够”“选项不匹配”分别提示。正常字段先处理，不因为缺岗位要求而停止个人资料填写。

更新时重启后台并重新加载扩展、刷新招聘页、重新推荐岗位；原有个人资料和项目保留。上述能力是本地可解释规则，不是不限范围的通用大模型推理，也不会猜造学校、日期、家庭等信息。未知网站的特殊控件仍需按实际页面验证。

## 0.5.1：学校下拉选择

学校、学历等字段支持等待原生下拉选项加载；对有语义标记的 combobox、Ant Design、Element、Select2 下拉控件，尝试展开、输入名称并选择唯一精确选项。仅输入搜索词不会算填写成功，重复或相似选项需要用户核对。学校未匹配时会提示检查国家、地区和中英文名称。

已在演示测试中验证原生延迟加载和可搜索下拉框。具体招聘网站仍需按实际控件验证；不宣称所有第三方组件及版本通用支持。更新后在扩展管理页重新加载，再刷新招聘页面即可，已有资料无需修改。

## 0.5.0：统一资料与智能填写

后台顶部统一管理个人信息、教育经历、项目经历、简历文件。本科、硕士可分开保存，设置一段默认教育经历，用于只有一组学校学历的表单。0.7.0 已增加明确多段教育表单的对应填写，填写后仍需核对。

日常使用：

1. 在后台录入资料和素材，点击“保存个人信息与教育经历”。
2. 在浏览器扩展管理页重新加载新版插件，刷新招聘网页。
3. 打开岗位详情，点击插件顶部“智能填写当前页面（含简历附件）”，自动识别并记住岗位、推荐材料，不需要复制粘贴。
4. 进入该岗位申请表，再点同一个按钮，自动填个人信息、项目并尝试上传简历。若申请页本身含岗位要求，可直接一次完成。

申请页没有岗位说明时，仅复用两小时内在同一网站（能识别租户时还需同租户）的岗位记录。插件会显示所用岗位名称，用户需核对；无法确定时提示先打开岗位详情。该方式不保证识别同一网站下所有不同岗位的跳转关系。

敏感字段仍单独确认。上传框不明确或自定义控件不支持时会提示手动处理。智能填写不会最终投递，也不会替换页面已有内容。原有①②③④分步按钮仍可使用。

旧插件资料：点击“导入旧插件中的个人资料”，再点击导入按钮；只补后台空项。家庭等信息由此转存到本机后台数据库，旧缓存仍保留。素材与项目无需迁移。更新后需要重启后台并重新加载插件。

## 0.4.0 更新

- 保存后的简历可编辑名称、方向说明与标签，无需重新上传文件。
- 项目列表可打开各个表述编辑，也可“以此为基础另存一个版本”。
- 插件可为每个项目手动切换表述，预览时间、职责和内容；选择会保留。
- 所有简历版本均可手动选择，不再只显示排名前五的文件。
- 缺失字段与不兼容控件使用中文说明；一次最多选择六个项目。

已有 0.3.0 素材无需迁移。更新代码并重启后台、重新加载插件后，请重新推荐一次岗位，以取得所有项目版本。编辑后台素材后，也需重新推荐来更新插件中的材料快照。网页中已有的文字会保留，切换项目版本后如需替换这些文字，请先手动清空相应字段。

## 能做什么

- 保存个人资料，识别空白字段并填写，已有内容跳过。
- 上传 PDF、TXT、Markdown 简历；PDF 需要包含可提取文字，暂不支持扫描件 OCR。
- 同一项目保存多个表述，各版本支持时间、角色、机构、职责、描述和标签。
- 从岗位详情页或选中的正文读取要求，也可以粘贴、编辑。
- 分别推荐简历附件和项目的最佳版本，允许勾选项目、调整附件。
- 填写常规项目输入框；在明确识别的项目区尝试点击“添加项目”。
- 将保存的简历文件放入指定附件框并触发网站上传事件。
- 保存岗位与选材结果，跳转申请页或重新打开插件后继续使用。

不自动点击最终投递按钮。混选项目只影响表单内容，上传的 PDF 仍是所选原文件，不会自动生成或改写 PDF。

## 安装与更新

需要 Python 3.10+ 和 Chrome / Edge，日常使用不需要 Node.js。

1. 下载源码，解压到固定文件夹。
2. 双击“启动后台.bat”。首次安装依赖需要联网，随后自动打开本机素材库。
3. 在浏览器输入 edge://extensions 或 chrome://extensions。
4. 开启“开发者模式” → “加载已解压的扩展程序”，选择含 manifest.json 的文件夹。
5. 在后台保存个人信息、教育经历，上传简历并添加项目表述。
6. 更新源码后，在扩展管理页面点“重新加载”，刷新招聘页面，并重启素材后台。

后台地址：http://127.0.0.1:8765 。保留启动窗口，关闭窗口即可停止服务。

## 先用演示页试填

素材库顶部有“打开试填演示页”链接。演示页包含岗位描述、项目栏、简历与头像上传框，不会向招聘网站发送信息。

1. 至少上传一份简历并保存一个项目版本。
2. 打开演示页，点击插件“① 读取当前岗位”，核对岗位内容。
3. 点击“② 按岗位推荐简历和项目”，选择附件和项目。
4. 点击“③ 将所选项目填入当前申请表”，检查绿色字段。
5. 点击“④ 检查当前页的附件上传框”，核对目标框，再点击上传。

真实网站上，先在岗位详情页完成①②，再进入该岗位申请表完成③④。插件保留上次岗位，换岗位时请重新读取、推荐。

## 如何录入项目

同一项目使用相同“项目名称”，不同方向使用不同“表述名称”，例如“通信版”“评测版”。相同项目与相同表述名称会更新已有版本。

点击项目列表的“编辑某版本”可载入原内容；编辑时项目名与版本名锁定，避免误存为另一项。点击“以此为基础另存一个版本”，输入新版本名即可保存另一种表述。简历卡片的“编辑名称与标签”只修改匹配信息，不会改写原附件。

时间按真实信息录入，如 2025-09 或“至今”。只知道月份而网站要求精确到日时，插件会提示手动填写，不编造日期。没有保存的角色、职责等字段也不会猜测。

关键词分仅用于文字匹配排序，不代表胜任程度或录取概率。匹配器只选择已有材料，不生成新经历。项目职责与项目简述分别填写。

## 兼容范围

| 场景 | 当前支持 |
| --- | --- |
| 有明确标签的文本框、文本域、原生下拉框 | 支持；已有内容跳过 |
| 多个独立项目卡片 | 按名称定位与填充 |
| 明确项目区域的添加按钮 | 尝试新增；不能确认时提示手动添加 |
| 原生文件上传框（含隐藏 input） | 放入文件、触发事件；上传结果以网站显示为准 |
| 自定义日期、下拉框、跨域 iframe、弹窗编辑器 | 可能需手动操作或专用适配 |
| 保存后再进入下一条的表单 | 暂不自动保存或跳步 |
| 登录、验证码、短信校验、最终投递 | 用户操作 |

已提供通用流程的演示测试，未宣称通过 Hotjob、北森、网易、中国联通正式网站的完整适配验证。反馈兼容问题时请去除真实个人信息。

## 数据与开源

- 文件、项目、个人与家庭资料、教育经历保存在 .data/。岗位、选择结果与旧版个人资料缓存保存在浏览器 chrome.storage.local；填写时以后台最新资料为准。
- 本地存储不等于加密存储，请使用受信任的个人电脑。
- 身高、体重、家庭与证件等信息需要页面单独确认才填写；没有询问时不填。
- 不使用云端 AI 或分析统计；点击附件上传后，文件交由招聘网站处理。
- 后台仅绑定 127.0.0.1，普通网页不能通过跨域接口读取素材。
- 网站权限用于识别不同招聘页；点击插件按钮时才读取岗位、填表或上传。
- .gitignore 排除了资料库、虚拟环境、个人文档和开发依赖。GitHub 网页上传不会自动遵守这些规则，请只上传源码。
- MIT 开源许可证见 LICENSE。本程序不会自动向 GitHub 发布。

## 开发与验证

手动运行后台：

~~~powershell
cd backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8765
~~~

运行基础检查（项目根目录）：

~~~powershell
node tests/core.test.js
node tests/projects.test.js
node tests/page-context.test.js
node tests/preference-values.test.js
node tests/education-records.test.js
backend\.venv\Scripts\python.exe backend/test_matcher.py
~~~

浏览器集成测试需要 Node.js、Playwright 和后台依赖：

~~~powershell
npm install
npx playwright install chromium
npm run test:e2e
~~~

主集成测试使用独立临时数据库、浏览器配置与8766端口，不占用真实素材库的8765端口。`tests/dropdowns.e2e.cjs` 使用独立合成表单，无需启动后台。可设置 TEST_BROWSER 为本机 Edge 的绝对路径，或用 TEST_PYTHON 指定 Python。覆盖字段同义词、不同标题表单、关联详情读取、结构化岗位、城市按序与兜底、不覆盖手填、学校搜索下拉、多段教育、日期精度、个人资料与项目附件等流程。

后台支持 JOB_AUTOFILL_DATA_DIR 指定隔离目录。提交问题或 PR 时请勿附带真实简历、联系方式、证件或家庭资料。
