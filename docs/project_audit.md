# 项目审查与实施记录

## 2026-10-11 初始检查

真实程序在 `job-form-autofill-extension/`，外层目录还有用户简历与生成文档，不属于发布源码，不读取、迁移或打包。根目录及程序目录均没有 `.git`，`git status` 返回 not a git repository；无法报告 Git diff 或既有提交，不擅自初始化仓库。

### 现有功能和技术栈

- 浏览器 Manifest V3 扩展，原生 JavaScript，识别个人资料、教育、项目、意向城市和上传控件，不自动提交申请。
- FastAPI / Pydantic / Uvicorn，SQLite 素材库，pypdf 文本提取，原生 HTML/CSS/JS 后台。
- 支持个人资料、多份 PDF/TXT/MD 简历、项目表述版本、关键词匹配；SQLite 与附件保存在 `.data/`。
- Python 匹配器测试、五套 Node 单元测试、Playwright 扩展及下拉回归测试。入口是 `backend/app.py` 和 `start-backend.bat`。

### 初始验证

- 五套 Node 单元测试通过（字段、项目、页面上下文、城市偏好、教育记录）。
- `backend/test_matcher.py` 通过。既有 Playwright 集成回归在最终验收中通过。
- 现有 Python 虚拟环境可用，Python 3.11；依赖版本采用范围，未提供锁定清单。

### 已发现的问题

1. 现有“智能”是本地关键词规则，并无大模型、Agent 状态机或面试功能；不可包装成已经实现的 Agent。
2. 上传接口只按后缀处理 PDF/TXT/MD，不支持 DOCX；未知文件会存为文本为空的附件，PDF 异常细节直接返回客户端；没有结构化提取或扫描件提示。
3. 没有会话历史、答案评分、追问、薄弱点、复习及报告。
4. 没有独立模型接口、超时重试、模型结果校验与结构化日志；没有环境模板、部署配置、统一测试入口。
5. 本地服务没有多用户认证，原 Origin/Host 规则仅面向 localhost；不能直接作为公网多租户服务部署。
6. 私人数据与源码同目录且 README 很长，开源需显式隔离与打包白名单；`.env.*` 也会误排除应提交的模板。
7. 原生页面缺少面试阶段、加载、模型失败恢复及完整历史交互。

## 保留与扩展决策

保留整个扩展、资料 API、SQLite 素材表、matcher、dashboard 设计风格和现有测试。不引入 React/Vue、向量数据库、LangChain/LangGraph；现有规模用显式 Python 状态机更容易验证。

增加 `backend/interview/` 独立模块、`/api/agent/*` API、`/interview` 原生页面。Agent 会话采用独立 SQLite 文件，不更改旧表和用户资料。模型提供商通过统一 `generate(task, payload, schema)` 接口替换，默认明确标识 Mock，真实服务采用可配置的 OpenAI 兼容 HTTP 接口。

## 最终架构和数据流（已实现）

上传校验/提取 → 结构化简历 → JD 解析 → 匹配分析 → 分层问题 → 等待用户回答 → 五维评价 → 有界追问 → 薄弱点记录 → 复习/最终报告。

所有模型输出经 Pydantic 校验；会话保存节点状态、事件、答案、评价和错误。模型失败不伪装成成功或自动换 Mock，保留失败阶段供重试。评分只辅助练习，真实性仅检查叙述与已提供资料的一致性，不能鉴定经历真伪；参考答案不得虚构项目、职责或量化成果。
